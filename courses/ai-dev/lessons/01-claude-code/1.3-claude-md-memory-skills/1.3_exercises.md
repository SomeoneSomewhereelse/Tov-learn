## תרגיל 1: עיצוב אישיות הפרויקט (קובץ טקסט - 20 דקות)
### הנחיות:
קובץ ה-`CLAUDE.md` הוא "תעודת הזהות" של הפרויקט שלכם מול Claude. בתרגיל זה ניצור קובץ ברמת הפרויקט (Project-level) עבור סטארטאפ פינטק ישראלי פיקטיבי בשם "PayIL".

### שאלות/משימות:
1. צרו קובץ בשם `CLAUDE.md` בתיקיית השורש של הפרויקט.
2. הגדירו בקובץ את המבנה ההיררכי הבא:
   * **Project Context:** תיאור קצר של המערכת (מערכת סליקה לעסקים קטנים בישראל).
   * **Tech Stack:** הגדרת טכנולוגיות (Node.js, React, MongoDB).
   * **Coding Standards:** הנחיות ספציפיות - למשל, "השתמש תמיד בשמות משתנים באנגלית, אך הוסף הערות קוד בעברית כשמדובר בלוגיקה עסקית מקומית (כמו חישוב מע"מ)".
   * **Response Style:** בקשו מ-Claude להיות תכליתי, קצר, וללא התנצלויות במקרה של שגיאה.
3. הפעילו את Claude Code בטרמינל (הקלידו `claude`) ובקשו ממנו: "כתוב פונקציה פשוטה לחישוב מחיר כולל מע"מ".
4. ודאו ש-Claude מגיב בהתאם להנחיות שהגדרתם (למשל, מוסיף הערות בעברית).

## תרגיל 3: יצירת Skill ראשון - Slash Command (מעשי - 45 דקות)
### הנחיות:
Skills מאפשרים להרחיב את היכולות של Claude. ניצור פקודת Slash מותאמת אישית שתבדוק תקינות של מספרי תעודת זהות ישראלית בקובץ.

### שאלות/משימות:
1. צרו תיקייה `.claude/commands/` בפרויקט שלכם.
2. צרו קובץ בשם `validate-tz.md` — שם הקובץ הופך אוטומטית לפקודה `/validate-tz`.
3. כתבו בתוך הקובץ הנחיות בפורמט Markdown רגיל (אין JSON, אין schema):
```
Scan the file provided as argument. Find all 9-digit numbers and validate each one using the Israeli ID checksum algorithm (modified Luhn). Report which are valid and which are invalid, with the line number for each.
```
4. צרו קובץ טקסט דוגמה `users.txt` עם כמה מספרי ת"ז (תקינים ושגויים).
5. ב-Claude Code, הריצו: `/validate-tz users.txt`.
6. תקנו את ה-Skill במידה ו-Claude לא מזהה נכון אילו מספרים תקינים ואילו שגויים.

## תרגיל 4: Skill לסריקת סודות לפני Push (מעשי - 40 דקות)
### הנחיות:
ניצור Skill שסורק את הפרויקט ומדווח על secrets חשופים — מריצים אותו ידנית לפני כל Push. Claude יכול גם להפעיל Skill בעצמו, כשהבקשה מתאימה ל-`description` שלו; כאן נריץ אותו ידנית.

### שאלות/משימות:
1. צרו `.claude/commands/scan-secrets.md`.
2. כתבו בקובץ הנחיות ל-Claude:
```
Scan all project files for exposed secrets: API keys, hardcoded passwords, connection strings, Stripe keys, AWS credentials, or any value that looks like a secret. For each finding report: filename, line number, and description. If nothing is found, confirm the project is clean.
```
3. צרו קובץ `.env.local` עם מפתח פיקטיבי `STRIPE_API_KEY=sk_test_123456789`.
4. הוסיפו גם secret מוסתר בקובץ `.js` רגיל — למשל: `const dbPass = "hunter2"`.
5. הריצו `/scan-secrets` ב-Claude Code.
6. ודאו שהוא מוצא את שניהם. האם הוא מציג את הערכים בפלט או מסתיר אותם? דונו בהשלכות.

## תרגיל 5: שומר קריאה עם Hooks (מעשי - 45 דקות)
### הנחיות:
Hooks הם מעקות בטיחות דטרמיניסטיים: Claude Code מריץ אותם בכל פעם שקריאת כלי מתאימה להגדרה, ו-Claude לא יכול לדלג עליהם. בתרגיל הזה נגן על קובץ "סודי" מזויף מפני **קריאה**, ונראה גם איפה ההגנה נגמרת. שום קובץ לא נמחק ולא נכתב, גם אם השומר נכשל.

### שאלות/משימות:
1. **הכנה.** בתיקייה `claude-advanced-lab` צרו שני קבצים:
   * `secret-demo.txt` עם השורה `FAKE_API_KEY=not-a-real-key`
   * `notes.txt` עם שורה כלשהי
2. **ה-Hook.** צרו את הקובץ `claude-advanced-lab/.claude/settings.json` (הגדרה ברמת הפרויקט, לא בהגדרות הגלובליות) עם התוכן הבא:
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Read",
        "hooks": [
          {
            "type": "command",
            "if": "Read(secret-demo.txt)",
            "command": "echo 'Blocked by hook: secret-demo.txt is protected' >&2; exit 2"
          }
        ]
      }
    ]
  }
}
```
   ב-Windows בלי Git Bash, החליפו את שורת ה-`command` בשורה:
   `"command": "[Console]::Error.WriteLine('Blocked by hook: secret-demo.txt is protected'); exit 2"`
3. **בדיקה שלילית.** הפעילו מחדש את Claude Code בתוך התיקייה, ובקשו **במילים** (לא עם אזכור `@secret-demo.txt`) לקרוא את `secret-demo.txt`. הקריאה נחסמת, ו-Claude חוזר על הסיבה שה-Hook כתב. *אם Claude מנסה מיד, מיוזמתו, דרך הטרמינל, זה שלב 5 שקורה מוקדם. רשמו את זה.*
4. **בדיקת ביקורת.** בקשו לקרוא את `notes.txt`. הקריאה עובדת כרגיל.
5. **העקיפה.** בקשו במפורש: "הרץ בטרמינל `cat secret-demo.txt`" (בלי Git Bash: `Get-Content secret-demo.txt`). התוכן מופיע.
   * *אם Claude מסרב,* הסירוב הוא התנהגות של המודל, לא אכיפה. רשמו מה קרה.
6. **המסקנה.**
   * Hook הוא מעקה בטיחות דטרמיניסטי **לקריאות הכלים שהוא תופס**. כלים אחרים (Bash, PowerShell, Grep) עדיין מגיעים לקובץ, וכנראה שגם אזכור `@file`, שאינו קריאה לכלי Read (לא נבדק). לכן Hook אינו מחסום אבטחה.
   * ל-Claude Code יש שכבות חזקות יותר:
     * **כללי deny** בהרשאות, שחוסמים גם `cat`/`head`/`tail`, אבל לא סקריפטים שפותחים קבצים בעצמם
     * **ה-sandbox**, שנאכף ברמת מערכת ההפעלה (macOS, Linux, WSL2)
   * האכיפה החזקה ביותר נמצאת מחוץ ל-Claude לגמרי: הרשאות של מערכת ההפעלה שהמשתמש שמריץ את הסוכן לא יכול לבטל.

   > **להמחשה בלבד — לא להריץ** (Linux):
   > `chmod 000 secret-demo.txt && sudo chattr +i secret-demo.txt`

   * "מחוץ להישג יד" פירושו מחוץ להישג ידו של כל תהליך שהסוכן יכול להפעיל.
7. **הערה על Y/N.** ל-Hooks אין טרמינל, ולכן Hook לא יכול לשאול "Y/N" בעצמו. כדי לבקש אישור, Hook מחזיר `permissionDecision: "ask"` (קריאת רשות: תיעוד ה-Hooks של Claude Code).

## תרגיל 6: אוטומציה עם פקודת /loop (מעשי - 30 דקות)
### הנחיות:
פקודת `/loop` מאפשרת ל-Claude לעבוד באופן אוטונומי על משימות שדורשות מספר שלבים או חזרות, עד להשלמתן.

### שאלות/משימות:
1. צרו קובץ `i18n-en.json` המכיל 10 מפתחות וערכים באנגלית (למשל: כפתורי התחברות, הודעות שגיאה, תפריט ניווט של אתר ישראלי).
2. צרו קובץ `i18n-he.json` ריק.
3. השתמשו בפקודת `/loop` ב-Claude Code עם ההנחיה הבאה:
   `/loop "Translate the keys from i18n-en.json to Hebrew and add them to i18n-he.json. Work in batches of 3 keys at a time. Stop the loop when all keys are translated and verified."`
4. צפו כיצד Claude מתכנן את המשימה, מבצע אותה בחלקים, בודק את עצמו, ויוצא מהלולאה (session-scoped) כשהמשימה מסתיימת.

## תרגיל 7 (משימת בית): The Autonomous QA Engineer (Routines & Cron)
### הנחיות:
בתרגיל המסכם, נחבר את כל מה שלמדנו: ניצור Routine אוטומטי עם Cron scheduling שיריץ סדרת בדיקות ועדכוני זיכרון ללא התערבות.

### שאלות/משימות:
1. **יצירת Skill לבדיקת קוד:** צרו Skill חדש בשם `qa-report` שסורק את כל קבצי ה-`.js` בפרויקט, מחפש פונקציות ללא הערות, ומייצר קובץ `QA_REPORT.md`.
2. **הגדרת Cron Routine:** בתוך ה-`CLAUDE.md` (תחת סקשן `# Cloud Routines`), הגדירו רוטינה חדשה.
3. כתבו ביטוי Cron (Cron expression) שיפעיל את הרוטינה בכל יום ראשון בשעה 08:00 בבוקר (תחילת שבוע העבודה בישראל).
4. הגדירו שהרוטינה תבצע את הפעולות הבאות:
   * תפעיל את ה-Skill `qa-report`.
   * תקרא את `MEMORY.md` כדי לבדוק אם יש סטנדרטים חדשים שהתווספו השבוע.
   * תשלח הודעת סיכום לטרמינל (או ללוג ייעודי).
5. **הגשה:** העלו את קבצי ה-`CLAUDE.md`, ה-Skills שיצרתם, קובץ ה-`MEMORY.md`, ו-`.claude/settings.json` עם ה-Hook ל-GitHub (Repository פרטי/פומבי) ושלחו את הלינק לבדיקה.

**הגישו עד השיעור הבא.**
